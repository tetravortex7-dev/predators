Stack: TSTL (`src/vscripts/` → `scripts/vscripts/`), Panorama (`src/panorama/` → `content/panorama/`), Valve KV (`scripts/npc/`). Build: `npm.cmd run build`.

## Core Workflow & Guardrails
- **Propose before coding on ideas:** On «придумай» / «предложи идею» / brainstorm requests, present ONLY 2–3 distinct options and DO NOT edit any code/files until the user explicitly confirms («делай» / picks one).
- **MCP first & clean relaunch:** Prefer `dota2-workshop` MCP (`addon_launch_tools` / VConsole2). For cold launch or relaunch, use the `relaunch-evo` skill (`steam.exe -applaunch 570 -novid -tools -addon evo -console -vconport 29000` — NEVER `-dev`, `-invisible`, `-silent`, hide, or minimize; wait for `PRE_GAME`/`GAME_IN_PROGRESS` & `[stall]` pass; guard `1331x922`).
- **NEVER self-test gameplay/UI in-game:** Do NOT use `dota_input`, `dota_click`, `dota_screenshot`, or `-evo_lvl` playtests unless explicitly asked. Build, run all static verifiers, ensure `script_errors=0` on launch if requested, and let the user test in-game.
- **Zero comments & 500-line limit:** ZERO `//`, `/* */`, or JSDoc in TS/Panorama/KV (except `<!-- kv3 ... -->`), and NO file > **500 lines**. Always run `verify-zero-comments`, `verify-modifier-loc`, `verify-file-size`, and `valve-tooltip-format --check` after edits, then wipe build/log/VConsole bloat with `clean-build-output` (+ `dota_send_console_command` `clear`).
- **No stubs / `TODO`:** Ship real systems; author owns content. Use `ARCHITECT.md` for module map. Keep `CHANGELOG.md` ultra-compact for LLMs (merge related changes into single bullets).
- **Architecture:** Modular SRP + OCP + `EventBus.ts` (`systems/`, `abilities/<hero>/`, `src/panorama/scripts/custom_game/`); `GameMode.ts` init-only; `snake_case` `evo_` prefix; constants in `game_constants.ts`; cheats `-evo_*` in `DevCheats.ts`; validate all `CustomGameEventManager` events (`PlayerID`, `IsAlive()`, range, match state); update `CustomNetTables` only on state change.
- **Dev/Tools mode (`IsInToolsMode()`):** Show all T1 branches in body draft (`BODY_DRAFT_T1_CHOICES = 3` in live only), keep `DEV_XP_MULTIPLIER = 2.0` (`200%` XP) enabled, and use the `dev-start-hero` skill whenever asked to test/spawn directly as a specific hero instead of Wisp (`DEV_START_BODY_ID` in `game_constants.ts`).

## Hero, Ability & Tooltip Rules
- **Native vs `ability_lua` & no Panorama ability hacks:** Shared vanilla spells fitting as-is use exact vanilla IDs in `data/branches/*.json` + `npc_abilities_override.txt` + `dmgFilter<Hero>.ts`. Whenever a branch needs its own icon, `MaxLevel`, or ability description on a shared slot, **ALWAYS use `ability_lua`** (check `reference/` + `tools/extract_vpcf.py` first) — NEVER override HUD icons or ability tooltips in Panorama. Read `evo-hero-branch` before editing heroes/branches/abilities/icons!
- **Rebirth + mandatory `_t3`/`_t4` split:** Every morph (`T0→T1→T2→T3→T4`) resets to **Lv.1 (`0` XP, `1` skill point)** with non-innate kit unlearned (`MaxLevel`: `T1: 3`, `T2: 4`, `T3/T4: 5`, `R: 3`). Tooltips MUST describe ONLY the current tier (NO `T1`–`T4` spoilers or future unlocks) — split any tier-changing ability/Innate into `<ability>_t3` / `<ability>_t4` (subclass cleanly in TS).
- **Innates, Slots & Icons:** Innates are strict `MaxLevel: 1` (`"Innate" "1"`, `"IsBreakable" "1"`) using KV `"hero_levelup"` (`_t3`/`_t4` for upgrades). Reserve `Ability1..6` with `evo_empty_slot_1..6` + `SwapAbilities` (never `""`/`"generic_hidden"`). Place `128×128` spellicons in `game/dota_addons/evo/resource/flash3/images/spellicons/`. For thematic icon sets, run **ONE `image-generator` agent sequentially** (NEVER parallel).
- **Valve HTML Tooltips (`valve-tooltip-format`):** Format ALL `data/localization/*.json` tooltips via the `valve-tooltip-format` skill (`<font color='#91a0b4'><b>...</b></font><br>` inline headers on hero abilities, NEVER `<h1>` outside `.IsItem`; `<br><br>`, `<b>`, semantic colors, Dispel Type span, `_Note0`/`_Note1`, `%var%` matching KV, RU+EN modifier loc).

## Source 2, Modifiers & Assets (`evo-source2-vfx` + `reference/INDEX.md`)
- **TS & Modifiers:** `strict: true`, minimal `any`; guard entities (`unit && !unit.IsNull() && IsValidEntity(unit)`), delete with `UTIL_Remove`, timings via `GameRules.GetDOTATime`. Read `evo-source2-vfx` skill before writing modifiers/precaching/particles: init ALL modifier fields inside `OnCreated()`/`OnRefresh()`, link without `IsServer()` on abilities (`link*Modifiers()` on managers, no circular `require`s), ALWAYS use `dotaModifierFunction`/`dotaModifierState`, guard `PassivesDisabled()` & `DamageFlag.REFLECTION`.
- **Precaching & Particles:** Sync-precache ONLY T0 starter, bosses, and deduplicated `.vmdl`/`.vpcf` sets in `addon_game_mode.ts`; load heavy heroes async via `LazyPrecacheManager` WITH `playerId`; never combine `PATTACH_ABSORIGIN_FOLLOW` with `SetParticleControlForward`; write plain scalars in custom `.vpcf` and verify with `resourcecompiler.exe -f` + `resourceinfo.exe -b DATA -baremode`.
- **Reference DBs & Data Pipelines:** Read `reference/INDEX.md` FIRST for Dota 2 sounds/particles/VPK/KV assets (`tools/extract_vpcf.py` for `.vpcf` CPs); NEVER run `tools/generate_reference_catalogs.py` except after major Dota 2 patches. Edit `data/localization/*.json`, `data/branches/*.json`, and `data/neutral_creeps.json` (never generated outputs directly).
