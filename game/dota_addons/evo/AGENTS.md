# AGENTS.md — Evo («Adapt. Win.»)

Stack: TSTL (`src/vscripts/` → `scripts/vscripts/`), Panorama (`src/panorama/` → `content/panorama/`), Valve KV (`scripts/npc/`). Build: `npm.cmd run build`.

## Core Rules
- **MCP first:** Use `dota2-workshop` MCP when available (KV/VScript/Panorama API, launch/reload, VConsole2). 2-step Tools launch: `addon_launch_tools` → wait `"Finished requesting news data"` → `dota_launch_custom_game evo zxc`.
- **NEVER hide or minimize Dota 2 window:** When launching Dota 2 from a closed state for the user to test, launch via `steam.exe -applaunch 570 -novid -tools -addon evo -console -vconport 29000` (without `-dev` or `addon_launch_tools`), wait `"Finished requesting news data"`, then send `dota_launch_custom_game evo zxc` over VConsole. Always verify `dota_diagnose` shows `game window` visible (`! (not visible)`). NEVER call `dota_window`, `dota_focus_window`, or `dota_screenshot(method="window")` if `dota_status` returns `1331x922` (Qt Asset Browser/Hammer handle, fixed in `Dota2_Workshop_MCP` `win32.ts`/`capture.ts` to prefer `SDL_app`). NEVER pass `-invisible`, `-silent`, hide, or minimize flags/commands.
- **Zero comments:** NO `//`, `/* */`, JSDoc in TS/Panorama/KV (except `<!-- kv3 ... -->`). Always verify with `verify-zero-comments` skill script.
- **File size & modularity:** Any file exceeding **500 lines** (as well as any large system) MUST be split logically into focused submodules.
- **Clean build output:** After every build, clean output logs & VConsole buffer down to 0 lines using `.agents/skills/clean-build-output/scripts/clean_build_output.py` (and `dota_send_console_command` `clear`) so tokens are never wasted re-reading bloated output.
- **No stubs / `TODO`:** Ship real systems; author owns content. Use `ARCHITECT.md` for module map. Maintain `CHANGELOG.md` ultra-compact for LLMs: logically group and merge related changes into single bullets instead of appending noisy per-edit lines.
- **Architecture:** Modular SRP + OCP + `EventBus.ts` (1 system = 1 file in `systems/`, abilities per hero in `abilities/<hero>/`, 1 UI widget = 1 file in `src/panorama/scripts/custom_game/`); `GameMode.ts` init-only; declarative data in `data/` & KV; `snake_case` `evo_` prefix; RU+EN localization (every visible modifier MUST have `DOTA_Tooltip_<mod>` + `_Description` in RU & EN; every custom ability tooltip MUST use native `%var%` / `%var%%%` inline bindings + `DOTA_Tooltip_ability_<name>_<var>` stat rows); constants in `game_constants.ts`; dev cheats `-evo_*` in `DevCheats.ts`.

## Source 2 & TSTL Invariants
- `strict: true`, minimal `any`; guard callbacks with `unit && !unit.IsNull() && IsValidEntity(unit)`; delete via `UTIL_Remove`; 1-based Lua / string keys; `if (!IsServer()) return;`; timings via `GameRules.GetDOTATime`; never hardcode `npc_dota_hero_*`.
- **CRITICAL modifier rules (where & how to build):**
  - **Where:** Hero/boss modifiers live with their ability in `src/vscripts/abilities/<hero>/`; standalone/global/creep modifiers live in `src/vscripts/modifiers/` (never inline inside `systems/`).
  - **Registration & linking:** Use `@registerModifier("modifier_evo_<name>")` + `LinkLuaModifier(name, "path/without_lua", LuaModifierMotionType.NONE)`. For standalone modifiers `require`d at startup (e.g. `NeutralCampsManager`), NEVER call `LinkLuaModifier` at module top level (runs before `Activate()`) — export a `link*Modifiers()` function and call it inside `<Manager>.init()` / `GameMode.initManagers()`. In ability files (`ScriptFile`), call `LinkLuaModifier` at top level WITHOUT `if (IsServer())` so both Server and Client VMs register modifiers cleanly; NEVER create circular `require` loops between ability files (extract shared helpers into a separate non-cycle helper module).
  - **Constructor trap (`OnCreated`):** Source 2 C++ does NOT run TSTL `____constructor()` on modifiers! Any `private x = 0` / `new Set()` field initializer is `nil` at runtime unless ALSO initialized explicitly inside `OnCreated(params)` (before `if (!IsServer()) return;` for shared fields; reset/update in `OnRefresh`, plus `??` fallbacks).
  - **Enums, guards & loc:** NEVER use raw `ModifierFunction`/`ModifierState` `const enum`s — always use `dotaModifierFunction("...")` / `dotaModifierState("...")` from `lib/dota_ts_adapter.ts`. Guard `OnIntervalThink`/`OnTakeDamage`/`OnAttackLanded` with `if (!IsServer()) return;`, entity validity checks, `PassivesDisabled()` (passives), and `DamageFlag.REFLECTION` (reflects). Every visible modifier (`IsHidden() => false`) MUST implement `IsDebuff()`, `IsPurgable()`, `GetTexture()`, and RU+EN `DOTA_Tooltip_<mod>` + `_Description` in `data/localization/*.json`.
- **CRITICAL hero ability slots & hotkeys (`Q/W/E/D/F/R`):** NEVER set `Ability1..6` to `""` or `"generic_hidden"` in `npc_heroes_custom.txt` — Source 2 leaves slots `0..5` as `nil`, causing `AddAbility` to append at slot `15+` and hotkeys to fail with *"Ability not learned"*. Always reserve `Ability1..6` with `evo_empty_slot_1..6` (never stripped), then `SwapAbilities` active abilities into slots `0..5`.
- **Appearance & Evolution:** Species swap via `HeroAppearance.replaceHeroPreservingState` (`ReplaceHeroWith`); same-species tiers & boss sets via `HeroAppearance.applyPreset` (wearables, scale, color, displayName). Bosses are `npc_dota_creature` (`ConsideredHero: 1`, `HasInventory: 1`).
- **CRITICAL precaching rules (no stalls, no `particles.dll` crashes):**
  - **Sync `Precache(context)` (`addon_game_mode.ts`):** NEVER call `PrecacheUnitByNameSync` across all `EVO_BODIES_CATALOG` entries (triggers 15–30s load freezes & `"Stall Detected"`). Sync-precache ONLY T0 starter (`tierIndex === 0`), boss `unitName` (`npc_dota_creature`), and **deduplicated** (`Set`) unique `.vmdl` / `.vpcf` paths (`PrecacheModel` / `PrecacheResource("particle", ...)` require `context`; verify `.vpcf` paths via `wearables_catalog.json` / `vpk_find`).
  - **Per-player async hero precache (`LazyPrecacheManager`):** Heavy `body.heroClass` units MUST be loaded via staggered `PrecacheUnitByNameAsync(heroClass, cb, playerId)` after startup (`precacheForPlayer(playerId)` on first hero spawn). ALWAYS pass `playerId` so Source 2 loads that player's Steam econ cosmetics/Immortals cleanly — omitting `playerId` causes `nonresident model ... may have been deleted` errors and `particles.dll` access-violation crashes!
  - **Safe `ReplaceHeroWith`:** Gate species swaps through `LazyPrecacheManager.ensureHeroReady(playerId, heroClass, cb)` before `ReplaceHeroWith`, and defer `UTIL_Remove(oldHero)` by `0.05s` so old hero particle attachments are not torn down mid-tick.
- **Hero Innates, Scepter/Shard & Talents:** All hero innates MUST use native Innate slot (`"Innate" "1"`, `"IsBreakable" "1"`, `DOTA_ABILITY_BEHAVIOR_PASSIVE | DOTA_ABILITY_BEHAVIOR_NOT_LEARNABLE | DOTA_ABILITY_BEHAVIOR_SKIP_FOR_KEYBINDS`; strip hidden vanilla innates). Clear Aghanim's Scepter/Shard on custom heroes for now. Use shared generic talents (`special_bonus_evo_*` in `scripts/npc/abilities/evo_generic_talents.txt` + `npc_heroes_custom.txt`) for all custom heroes until per-hero talents are designed.
- **Panorama UI:** 100% native Dota 2 Reborn style (`s2r://panorama/styles/dotastyles.vcss`, `s2r://panorama/images/hud/reborn/...`). No decorative badges, glowing fonts, or inactive indicators.
- **Security:** `CustomGameEventManager` events are untrusted — validate `event.PlayerID`, `IsAlive()`, resources, distance, match state. Write `CustomNetTables` only on state change.
