# Source 2 Modifiers, Precaching & Particles Guide

## 1. Modifier Architecture & Traps
- **Placement:** Hero/boss modifiers live beside their ability in `src/vscripts/abilities/<hero>/`; standalone/global/creep modifiers live in `src/vscripts/modifiers/` (never inline inside `systems/`).
- **Registration & linking:** Use `@registerModifier("modifier_evo_<name>")` + `LinkLuaModifier(name, "path/without_lua", LuaModifierMotionType.NONE)`.
  - For standalone modifiers `require`d at startup (e.g. `NeutralCampsManager`), NEVER call `LinkLuaModifier` at module top level (runs before `Activate()`) — export a `link*Modifiers()` function and call it inside `<Manager>.init()` / `GameMode.initManagers()`.
  - In ability files (`ScriptFile`), call `LinkLuaModifier` at top level WITHOUT `if (IsServer())` so both Server and Client VMs register cleanly. NEVER create circular `require` loops between ability files (extract shared helpers into a non-cycle helper module).
- **Constructor trap (`OnCreated`):** Source 2 C++ does NOT run TSTL `____constructor()` on modifiers! Any `private x = 0` / `new Set()` field initializer is `nil` at runtime unless ALSO initialized inside `OnCreated(params)` (before `if (!IsServer()) return;` for shared fields; reset/update in `OnRefresh`, plus `??` fallbacks).
- **Enums, guards & loc:** NEVER use raw `ModifierFunction`/`ModifierState` `const enum`s — always use `dotaModifierFunction("...")` / `dotaModifierState("...")` from `lib/dota_ts_adapter.ts`. Guard `OnIntervalThink`/`OnTakeDamage`/`OnAttackLanded` with `if (!IsServer()) return;`, entity validity checks, `PassivesDisabled()` (passives), and `DamageFlag.REFLECTION` (reflects). Every visible modifier (`IsHidden() => false`) MUST implement `IsDebuff()`, `IsPurgable()`, `GetTexture()`, and RU+EN `DOTA_Tooltip_<mod>` + `_Description` in `data/localization/*.json`.

## 2. Appearance, Species Swap & Precaching (No Stalls, No `particles.dll` Crashes)
- **Appearance:** Species swap via `HeroAppearance.replaceHeroPreservingState` (`ReplaceHeroWith`); same-species tiers & boss sets via `HeroAppearance.applyPreset` (wearables, scale, color, displayName). Bosses are `npc_dota_creature` (`ConsideredHero: 1`, `HasInventory: 1`).
- **Sync `Precache(context)` (`addon_game_mode.ts`):** NEVER call `PrecacheUnitByNameSync` across all `EVO_BODIES_CATALOG` entries (triggers 15–30s load freezes & `"Stall Detected"`). Sync-precache ONLY T0 starter (`tierIndex === 0`), boss `unitName` (`npc_dota_creature`), and **deduplicated** (`Set`) unique `.vmdl` / `.vpcf` paths (`PrecacheModel` / `PrecacheResource("particle", ...)` require `context`; verify `.vpcf` paths via `wearables_catalog.json` / `vpk_find`).
- **Per-player async hero precache (`LazyPrecacheManager`):** Heavy `body.heroClass` units MUST load via staggered `PrecacheUnitByNameAsync(heroClass, cb, playerId)` after startup (`precacheForPlayer(playerId)` on first hero spawn). ALWAYS pass `playerId` so Source 2 loads Steam econ cosmetics/Immortals cleanly — omitting `playerId` causes `nonresident model ... may have been deleted` errors and `particles.dll` access-violation crashes!
- **Safe `ReplaceHeroWith`:** Gate species swaps through `LazyPrecacheManager.ensureHeroReady(playerId, heroClass, cb)` before `ReplaceHeroWith`, and defer `UTIL_Remove(oldHero)` by `0.05s` so old hero particle attachments are not torn down mid-tick.

## 3. Particle Authoring & Spawning (Zero Invisible FX)
- **TS/Lua (`ParticleManager`):** When manually orienting (`SetParticleControlForward`), use `ParticleAttachment.ABSORIGIN` (`SetParticleControl(pfx, 0, pos)`) or `SetParticleControlEnt(..., PATTACH_POINT_FOLLOW, "attach_hitloc", ...)` per `reference/vanilla_lua_abilities/` — NEVER combine `PATTACH_ABSORIGIN_FOLLOW` with `SetParticleControlForward(pfx, 0, ...)`. Check `reference/particles/` + `tools/extract_vpcf.py` for required ControlPoints (`CP0/CP1/CP2/...`).
- **Custom/recolored `.vpcf` in `content/dota_addons/evo/particles/`:** `resourceinfo.exe` prints compiled `PF_TYPE_LITERAL` dicts / `m_vecTexturesInput` / `m_nOutputBlendMode`, which `resourcecompiler.exe` silently compiles to `0.0` in unversioned/KV3 source files! ALWAYS write plain scalars in source `.vpcf` (`m_nParticlesToEmit = <N>`, `m_flInitialSpeedMin = ...`, `m_hTexture = resource:"..."`, `m_bAdditive = true`), strip `C_OP_ControlpointLight` / `m_nScaleCP1/CP2` unless driven by C++ (`DoCleaveAttack`), compile via `resourcecompiler.exe -i "<file.vpcf>" -f`, and verify the compiled `.vpcf_c` DATA block with `resourceinfo.exe -b DATA -baremode` (`m_nParticlesToEmit > 0`). Always precache in `addon_game_mode.ts`.
