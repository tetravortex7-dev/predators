# Evo Hero, Branch & Ability Engineering Guide

## 1. Native Abilities vs `ability_lua` (No Panorama Ability Hacks!)
1. **Shared vanilla ID (`T1` / single-branch spell):** Whenever a vanilla Dota 2 spell fits AS-IS (and no other branch needs a different icon, `MaxLevel`, or ability description for that same ID), use its **exact vanilla Dota 2 ability name** in `data/branches/*.json` + KV override in `scripts/npc/npc_abilities_override.txt` + stat scaling in `src/vscripts/data/damage/dmgFilter<Hero>.ts` (`HERO_DAMAGE_MODULES` in `damage_rules.ts`).
2. **Branch-specific icon, `MaxLevel`, or description = ALWAYS `ability_lua` (`100%` of cases):** Dota 2 KV cannot inherit `"BaseClass" "<vanilla_spell>"`. Therefore, whenever a branch needs its own icon (`AbilityTextureName`), `MaxLevel`, mechanics, or custom tooltip on a slot whose vanilla spell is already used by another branch, **ALWAYS implement a clean `ability_lua` in `src/vscripts/abilities/<hero>/`** (inspecting `reference/vanilla_lua_abilities/INDEX.md` and `.vpcf` CPs via `tools/extract_vpcf.py` first!). **NEVER** override HUD ability icons (`DOTAAbilityImage`) or `#DOTAAbilityTooltip` descriptions in Panorama — Panorama UI hooks are strictly reserved for engine gaps with no KV/Lua alternative (like `evo_aghs_tooltip.ts`).
3. Keep RU+EN overrides/tooltips synced in `data/localization/hero_*.json`.

## 2. Evolution Morphs & Mandatory Per-Tier Splitting (`_t3` / `_t4`)
- **Rebirth on EVERY morph:** Every evolution (`T0->T1`, `T1->T2`, `T2->T3`, `T3->T4`) MUST reset the hero to **Level 1 (`0` XP, `1` skill point)** via `ReplaceHeroWith` (even on same-species `heroClass` transitions) and leave all non-innate kit abilities **unlearned (`level 0`)** so players re-level from scratch; only the Innate is auto-leveled. Ability `MaxLevel`: `T1: 3`, `T2: 4`, `T3/T4: 5`, `R: 3`.
- **Mandatory `_t3` / `_t4` split:** Tooltips and stats MUST show ONLY the current tier's actual behavior (NEVER leak `T1`–`T4`, `(T3)`, `T3+`, or upcoming unlocks). Whenever any ability or Innate gains ANY new mechanic or upgrade across `T2 → T3 → T4`, split it into separate IDs (`<ability>_t3`, `<ability>_t4`, subclassing cleanly in TS without duplicating logic) with tier-accurate `MaxLevel` & `AbilityValues` in KV, wired in `data/branches/*.json`, and documented 100% in RU+EN tooltips. NEVER share one ability ID across tiers whose behavior differs.

## 3. Hero Slots, Innates, Shards & Talents
- **Ability slots (`Q/W/E/D/F/R`):** NEVER set `Ability1..6` to `""` or `"generic_hidden"` in `npc_heroes_custom.txt` (causes slots `0..5` to be `nil` and hotkeys to fail with *"Ability not learned"*). Always reserve `Ability1..6` with `evo_empty_slot_1..6` (never stripped), then `SwapAbilities` active abilities into slots `0..5`.
- **Native Innates (`MaxLevel: 1` strictly):** Always use `"Innate" "1"`, `"IsBreakable" "1"`, `"MaxLevel" "1"`, `DOTA_ABILITY_BEHAVIOR_PASSIVE | DOTA_ABILITY_BEHAVIOR_NOT_LEARNABLE | DOTA_ABILITY_BEHAVIOR_SKIP_FOR_KEYBINDS` (strip hidden vanilla innates). NEVER create multi-level Innates or space-separated multi-level `AbilityValues` on an Innate — define separate `MaxLevel: 1` tier Innates instead. Hero-level-scaling Innates MUST use Valve's `"hero_levelup"` (+ optional `"levelup_interval"`) inside `AbilityValues` + `%var%` bindings and `GetSpecialValueFor` (never static `min–max` text or manual Lua level formulas).
- **Aghanim's Shard on dynamic `AddAbility` branches:** Set `"HasShardUpgrade" "1"` in KV, use `"special_bonus_shard"` inside `AbilityValues` (plain scalar display keys without `"RequiresShard" "1"` if shown before purchase), check `HasModifier("modifier_item_aghanims_shard")` in TS (NEVER `super.GetCooldown` or non-existent `HasShard()`), preserve `modifier_item_aghanims_shard` in `hero_state_transfer.ts`, and define RU+EN `DOTA_Tooltip_ability_<name>_Shard_Description` (`src/panorama/scripts/custom_game/evo_aghs_tooltip.ts` handles HUD/tooltip injection automatically; clear Scepter until designed).
- **Talents:** Use shared generic talents (`special_bonus_evo_*` in `scripts/npc/abilities/evo_generic_talents.txt` + `npc_heroes_custom.txt`) until per-hero talents are designed.

## 4. Panorama UI & Cohesive Spellicon Sets
- Panorama must match native Dota 2 Reborn (`s2r://panorama/styles/dotastyles.vcss`, `s2r://panorama/images/hud/reborn/...`) with zero decorative badges or glowing fonts.
- Custom spellicons: place raw `128×128` `.png` files directly in `game/dota_addons/evo/resource/flash3/images/spellicons/<name>.png` and set `"AbilityTextureName" "<name>"` (KV) / `GetTexture()` (modifier). NEVER create `.vdata`, `*_png.vtex_c`, `panorama/images/spellicons/` duplicates, or XML preloads.
- **Cohesive icon sets (`image-generator`):** NEVER spawn multiple `image-generator` agents in parallel for a hero/branch — launch ONE `image-generator` agent sequentially in a single conversation (creating an anchor icon first, then referencing it for the rest) so art style, palette, lighting, and framing match.
